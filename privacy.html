Privacy and data handling

Privacy Policy

Effective date: 12 October 2026 · Operator: the owner of the GitHub account Afreedomlife · Contact: GitHub Issues (public, no secrets)

TECTOR Archive is a private-use desktop backup workflow using the independent, open-source rclone software and the owner's Google Drive account. The informational website does not request Google authorization or receive backup files.

1. What data is accessed

When the owner separately configures rclone on their own Windows computer, rclone may read only locally selected files and associated metadata, such as file names, relative paths, size and modification time, for the purpose of copying backups to Google Drive. The uploaded Drive files contain the backup data selected by the owner.

The app is configured to request the Google Drive OAuth scope https://www.googleapis.com/auth/drive.file. This scope permits access to files that the app creates or that the owner specifically grants it access to; it is not intended to grant broad access to every file in the owner's Drive. No scope beyond what the consent screen lists should be assumed.

2. Purpose and processing

Google user data is used only to authenticate access to the owner's Drive, upload and verify selected backups, list files the app can access, and, if explicitly initiated by the owner, restore copies. A copy-only procedure is preferred; the backup workflow does not authorize automatic deletion of original local files.

Selected file contents and metadata are transmitted between the owner's PC and Google Drive over the secure connections provided by the Google Drive API and rclone. The public website has no upload endpoint, user database, or backend receiving backup contents.

3. Credentials and storage

Google OAuth authorization occurs in Google's authentication flow. rclone stores its connection configuration and OAuth tokens locally on the owner's computer. These credentials must remain private and should be protected by operating-system permissions and, when configured, rclone's encrypted configuration feature. No client secret, refresh token, access token or private file is published in this repository or collected through this website.

Backup files are stored in the owner's Google Drive and are subject to the Google account's storage and retention settings. File manifests and local logs, if the owner chooses to create them, remain under the owner's control.

4. Sharing, sale and advertising

The operator does not sell, rent or share Google user data for advertising, profiling or model training. No third-party analytics or ad scripts are included in this website. Google processes the uploaded files as the selected cloud storage provider; rclone is the separate software used to transfer them.

This site is hosted by GitHub Pages. GitHub may process normal hosting and access information in accordance with GitHub's privacy statement. This informational site has no custom analytics, cookies or sign-in form.

5. Retention and deletion

The app operator runs no central service that retains copies. Cloud backup files remain in the owner's Drive until the owner deletes them using Google Drive or an explicitly chosen command. Local rclone configuration and tokens remain on the owner's device until the owner deletes or replaces that configuration. Revoking OAuth access does not delete files previously copied to Google Drive.

6. Your control and revocation

  • Review or revoke app access in your Google Account's third-party connections.
  • Remove the configured rclone remote and its saved credentials from the local rclone configuration when no longer needed.
  • Inspect, download or delete any archived file directly from your own Google Drive.
  • To ask about this informational page, open a public GitHub Issue without posting sensitive information.

7. Updates

This notice may change when the backup workflow changes. Material changes will be posted on this website with an updated effective date. No additional use of Google user data is implied without an appropriate authorization request.
